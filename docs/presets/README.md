# 编码工作流实验预设

[claude-code-inspired.json](./claude-code-inspired.json) 是可导入的 pi-web-ui 预设，借鉴调查、根因修复、持续执行和验证闭环等编码实践。它不是 Anthropic 官方预设，也未复制或核对某个版本的 Claude Code 系统提示词，不保证提高所有模型或任务的表现。

## 导入与恢复

1. 在设置的预设管理中，先保存并导出当前配置，作为恢复副本。
2. 导入本目录的 JSON，检查导入预览，再应用“Claude Code 风格编码（实验）”。
3. 在提示词设置中检查展开结果；主会话的后续回合使用新模板。需要恢复时应用原先保存的预设。

该文件仅包含 `promptTemplate`、`promptOverrides`、`promptDisabled` 三个字段。模板保留全部 11 个动态来源，并在末尾追加英文编码工作流，以便工具说明、项目规范、技能及工作目录继续由运行环境生成。`append` 仍保留自动内容，包括已有的 `APPEND_SYSTEM.md`。

应用后会替换当前组合模板、清空已有逐段覆盖，并重新启用所有提示词段。若依赖自定义 `soul`、`guidelines` 或其他逐段覆盖，应用后需要自行合并；导入前请查看预览。模型、思考强度、工具、权限和上下文参数未包含在该预设中。预设应用仍经过宿主的统一设置与工具门控流程。

该主会话模板不会自动覆盖子代理角色模板。计划、审查、审批等模式约束仍由宿主执行；此工作流要求尊重这些约束。

## 对照评估

在相同仓库提交、模型版本、思考强度、工具权限及任务输入下，分别使用原配置和实验预设。每次从独立的新会话开始，避免先前调查结果影响比较。选择几项真实修复和功能任务，记录：

- 是否定位正确入口、调用链及权威状态，是否解决根因。
- 修改是否完整，是否引入无关重构或遗漏调用方。
- 是否完成相关检查，报告的结果是否与实际执行一致。
- 回归情况、人工返工量，以及时间和 token 成本。

提示词效果具有随机性，单次结果不足以证明整体改善。若差异源自工具输出丢失、上下文恢复或执行错误，应修复对应机制。
