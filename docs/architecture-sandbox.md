# 沙盒工作区

沙盒是服务端管理的项目副本。文件工具只能访问受管目录；没有操作系统隔离后端时，不允许通过宿主 shell、解释器、任意代码或未知工具执行副作用。沙盒不应被宣传为允许任意程序执行的容器。各执行引擎必须在执行前具备同等拒绝能力，不具备时拒绝在沙盒启动任务。

## 身份与准入

沙盒身份绑定执行会话并继承到子代理。切换 cwd、派生执行者、恢复会话均不能解除边界；沙盒父执行者不得通过指定外部 cwd 或 worktree 派生突破边界。注册记录失效、受管目录身份未知、生命周期操作正在进行时拒绝执行，不能退化成普通工作区。

文件路径检查同时覆盖词法路径与真实路径，拒绝软链接、junction、硬链接及特殊文件。宿主工具按明确能力放行，未知能力默认拒绝；不得用扩充 shell 正则的方式承诺任意代码隔离。插件、MCP、解释器、终端输入和工具编排入口同样属于执行边界。SDK 搜索工具可能继承宿主命令配置，`grep/find` 在提供专用安全实现前同样拒绝。

沙盒运行时不加载磁盘扩展、SDK 内置扩展、插件或 MCP 工具；最终 SDK 执行前检查还要验证工具定义和 execute 的原始引用，防止同名替换获得信任。当前最终工具白名单也不放行沙盒内模型派发子代理；宿主子代理入口仍验证父级身份和 cwd，防止其他路径绕过。沙盒内管理工具仅可列出自身元数据、将自身转为永久保留；导入、源项目对比、导出、重置、写回、销毁由沙盒外的控制面发起。用户在 UI 上进行预览和管理不受此模型工具限制。

## 基线与写回

导入保存独立基线。差异表示沙盒相对基线的修改；写回使用基线、当前源项目和当前沙盒三方比较，只提交沙盒改动，保留源项目独立产生的文件与修改。双方同时修改同一目标时拒绝并报告冲突。

写回绑定预览版本：用户预览之后任一参与内容发生变化，必须重新预览。执行时重新验证真实目标路径，拒绝沿目标软链接、junction 或其他不安全目标写入。写入先在源项目同一文件系统暂存并保留恢复映射，失败回滚前核对目标仍为本次写入内容；发现源端并发修改则保留当前内容与备份并报告恢复路径。目录删除按深度逆序执行，失败不能返回成功。旧沙盒缺少可信基线时允许查看和导出，但拒绝直接写回。

## 生命周期与持久化

同一 data-dir 内各会话共享仓库，注册变更串行提交并原子持久化。持久化失败必须向调用方报告，不能先发布成功运行态。

重置、写回、销毁先冻结新执行，协调全部持有该沙盒的运行时、子代理和相关终端，等待在途操作退出后再修改文件。失败保留可识别且受保护的状态，供重试。销毁完成前不得撤销沙盒身份；停止范围按沙盒确定，不影响其他项目或用户终端。

重置准备完整的新副本后提交，避免边删除边复制导致新旧文件混合。销毁先将内容重命名到可恢复的暂存位置，再提交注册表删除；提交失败还原目录，清理失败报告恢复路径。文件占用或清理失败不能仅警告后报告成功。复制逐文件验证副本与源快照的内容、权限一致，扫描限制 15,000 个条目、64 MB 单文件和 512 MB 累计文件字节，避免无界占用。

## 验证重点

回归必须覆盖：源项目独立新增和修改、双方冲突、删除与类型变化、预览过期、目标软链接/junction、并发创建、持久化失败、注册身份失效、运行中重置与销毁、父子权限继承、终端和未知工具旁路，以及不支持隔离的引擎拒绝启动。

核心实现位于 `server/sandbox-service.ts`、`server/sandbox-tool.ts` 和各引擎会话入口。协议位于 `server/protocol.ts`，前端入口为 `web/src/components/SandboxModal.tsx`。
