输入框高度自适应失控 & 正文遮挡治理

针对用户反馈的「输入框高度一直增加直到遮挡正文、无法下拉缩小、无文字时也被巨大保底撑满」缺陷，从根因剖析、交互演进到工程落地的 4 套完善方案合集与可交互沙箱原型。

现行代码的 4 大致盲性逻辑缺陷（为什么无法减小？为什么空内容也撑满？）

1. Math.max 产生“只能增不能减”死锁

代码中写了 Math.min(Math.max(scrollHeight, composerH), cap)。当用户输入长文本导致 scrollHeight 达 500px 时，向下拖拽把 composerH 降到 150px 根本无效，scrollHeight 始终死死顶住高度！

2. 720px 绝对像素脱离视口安全保障

硬编码了 COMPOSER_MAX_H = 720。1080P 或笔记本视口常只有 750~850px，输入框加上工具条直接占满 100% 视口，将正文区（.messages）挤压至 0px 彻底不可见。

3. localStorage 持久化“幽灵高度”

一旦拉高或误触，保底高度存入 localStorage。之后清空文字、新建对话，输入框依然以 720px 撑开整个屏幕（如截图所示无文字却占全屏），而“双击恢复”隐藏在隐形细线上无法被发现。

4. 抓手重叠与操作盲区

顶部拖拽条平时 opacity: 0，当输入框被撑大到顶边时，抓手与快捷短语药丸严重重叠挤占，鼠标极易触发短语点击，根本摸不到 14px 的细窄抓手。

方案 1 机制：视口百分比上限 + 双向自由裁剪

彻底解决“只能变大不能缩小”以及“空文本霸屏”的黄金法则：

动态相对上限：摒弃 720px，采用 maxHeight = min(40vh, 320px)，正文随时拥有 ≥60% 安全视口。
双向真实控制：用户拖动时，设置的是目标限高 userH。当 userH < scrollHeight 时，强制激活内部纵向滚动 overflow-y: auto，让用户能随时向下拉扁输入框看上面的正文！
空状态智能回缩：无内容时始终紧凑（40px），用户拖拽的高度仅作为“长文本时的容纳上限”，决不再出现截图中的巨型空框！
// ChatInput.tsx 核心计算公式重构 const MAX_SAFE_CAP = Math.min(window.innerHeight * 0.42, 320); let targetH = COMPOSER_AUTO_H; if (!text.trim()) { targetH = COMPOSER_MIN_H; // 空文本绝对不撑满 } else if (userH != null) { // 允许向下自由压缩！超出部分交给内部滚动 targetH = Math.min(userH, MAX_SAFE_CAP); } else { targetH = Math.min(ta.scrollHeight, MAX_SAFE_CAP); } ta.style.height = `${targetH}px`; ta.style.overflowY = ta.scrollHeight > targetH ? "auto" : "hidden";

方案 2 机制：Splitter 刚性安全门禁

将消息流与输入框作为真正的 Flex 分割视窗：

正文刚性下限：声明 .messages { min-height: 240px; flex: 1 1 auto; }，输入框绝对无法侵占该区域。
物理阻尼碰撞：拖动分割线时，如果正文高度即将低于 240px，拖动手势立即进入硬阻尼锁定，防止穿透。
大屏多任务友好：适合桌面宽屏 IDE 风格，两块区域各自拥有独立滚动条，权责分明。
/* CSS 刚性布局防侵入 */ .main-chat-container { display: flex; flex-direction: column; height: 100vh; } .messages { flex: 1 1 auto; min-height: max(240px, 40vh); /* 绝对不可侵犯的正文空间 */ overflow-y: auto; } .composer-pane { flex: 0 0 auto; max-height: calc(100vh - 240px); /* 动态锁死上限 */ }

方案 3 机制：长文编辑与日常聊天分离 (强烈推荐)

现代顶级 AI 应用（Claude 3.7 Projects、Cursor Composer、GitHub Copilot）普遍采纳的行业终极范式：

主界面极致紧凑：输入框高度牢牢锁死在 40px~140px（不超过 5 行）。绝不对正文产生压迫感。
按需展开沉浸空间：粘贴多行内容或内容变长时，右下角高亮提示「⛶ 展开编辑」，弹窗中支持舒适排版与 Token 估算。
心智彻底解脱：用户再也不用在局促又容易变形的主聊天框里提心吊胆地上下拉扯，从根源上消除高度自适应的边际灾难。

方案 4 机制：离散档位吸附 (Discrete Magnetic Tiers)

消除像素级拖拽的不确定性，提供明确预期：

三种固定心智模型：44px（快速指令）、160px（多行提问）、280px（大段代码审阅），严格封顶 280px。
状态一目了然：右上角始终标明当前档位，随时可点切，不会出现“不知道当前处于什么保底高度”的隐形困扰。
结合拖拽吸附：如果用户手动拖拽，松手时自动平滑磁吸至最近的一档（Magnetic Snap），手感顺滑。
