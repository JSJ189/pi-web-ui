# 📓 笔记（notes 插件）

笔记 · 待办 · 日程提醒 三合一，装成 pi-web-ui 的界面插件：

- **笔记**：Markdown 正文 + 标签 + 置顶 + 搜索，左右两栏，输入即存。
- **待办**：勾选 / 优先级 / 截止时间 / 重复（每天·每周·每月），逾期与今天到期高亮。
- **提醒**：一次性 · 每天 · 每周几 · 每月几号 · 每 N 分钟 · 自定义 cron，**服务端定时**
  （重启不丢、停机错过的那次会补），到点在浏览器里弹站内通知条 / 桌面通知 / 提示音。
- **议程**：把逾期待办、今天、明天、未来 7 天、无日期的条目和接下来 14 天的提醒排成一条时间线。
- **日历**：月视图（周一起排，6×7 格），把待办按截止日、把**重复提醒按当月每一天的实例**画出来，点某天看那天的清单。
- **Markdown 镜像**（可选，默认关）：在设置里开开关 + 填一个绝对目录，每次改动把每篇笔记写成 `.md`、另生成 `_todos.md` / `_reminders.md` 汇总 —— 给 Obsidian / git 用。
- **一个入口**：顶栏 **📓 笔记** 打开**可自由拖拽的全局浮窗**（位置/尺寸/开合/最小化状态记忆，
  可缩成带角标的小贴片），窗口里的 **⚙** 打开设置覆盖层（通知开关 / 语言 / 导入导出 / 重置位置）。
  本插件**没有独立视图 tab**（`manifest.view: false`）—— 浮窗就是它的全部界面。
- **AI 也能写**：5 个工具 + 4 个斜杠命令。

## 安装

设置 →「界面插件」→「插件市场」里的 **笔记** 一键安装；或：

```bash
pi-web-ui install xing-shuyin/pi-web-ui/plugins/notes
```

装完刷新页面：顶栏出现 📓 笔记（拖不到？见下面「界面布局」）。

## 用法

| 做什么 | 怎么写 |
| --- | --- |
| 加待办 | 待办 tab 的输入框：`交周报 明天 18:00 #工作 !!`（认 `今天/明天/后天`、`周五/下周三`、`5-6`、`18:00`、`9点半`、`#标签`、`!`~`!!!` 优先级） |
| 加提醒 | 提醒 tab：`每天 9:00 吃药`、`每周五 18:00 复盘`、`每月 1 号 9:00 交房租`、`每30分钟 起身`、`明天 21:30 交作业` |
| 加笔记 | 笔记 tab：输入标题回车 → 右侧写正文（Markdown 原文，不渲染） |
| 改一条 | 点列表任意一行 → 打开编辑器；改完不用保存（输入即存，400ms 合并写入） |
| 推迟提醒 | 提醒行上的 ⏰，或编辑器里的「推迟 10 分钟」：临时改成一次性，响过之后**自动还原**原来的重复档 |
| 快速捕获 | 快捷键 `Ctrl/Cmd+Alt+N`（打开浮窗并把光标放进输入框）；斜杠命令 `/note`、`/todo`、`/remind` |
| 批量整理 | 待办页脚「清除已完成」；浮窗 ⚙（设置覆盖层）里导出 JSON / Markdown、导入 JSON（合并或整库覆盖） |
| 看一个月 | 顶部「日历」tab：‹ › 翻月、点「今天」回到本月、点格子看当天清单 |
| 镜像给 Obsidian | 设置 →「界面插件」→ 笔记 → 勾「镜像成 Markdown 文件」+ 填绝对目录（首次写入浏览器会要一次目录授权）；也可 `/notes-mirror` 手动同步一次 |

### 给 AI 用（设置 →「工具」页可逐条关）

| 工具 | 作用 |
| --- | --- |
| `notes_list` | 读笔记/待办/提醒（带 id；支持 `kind` / `query` / `tag` / `include_done` / `limit`） |
| `notes_add` | 记一条笔记（Markdown 正文） |
| `notes_update` | 按 id 改/删笔记（`append` 追加正文） |
| `notes_todo` | 待办增改勾删（`add`/`update`/`done`/`undone`/`remove`/`clear_done`，可带 `due`/`priority`/`repeat`/`tags`） |
| `notes_reminder` | 提醒增改删/推迟（`at` / `daily_at` / `weekly_at`+`weekdays` / `monthly_at`+`day_of_month` / `every_minutes` / `cron`） |

对着对话说「记一下今天会上定的三件事」「提醒我周五 18:00 交周报」「我还有什么没做的」，
agent 就会自己调这些工具；注册的工具也能在设置里逐条关掉（与其它插件工具同一套开关）。

## 数据与边界

- 数据落在 **`<dataDir>/notes/store.json`**（默认 `~/.pi-web/notes/store.json`），原子写；
  导入前会留一份 `store.json.bak`。**删插件不删数据**，重装即接着用。
- 提醒按**服务器本地时区**触发（不是浏览器的时区）：服务端到点把提醒放进「待送达队列」，
  浏览器连着就立刻收到并弹提示；**浏览器没开**时留着，下次打开补送一次（补送过的不会重复弹，
  同浏览器去重记在 localStorage）。界面上「下次 …」显示的时刻按**浏览器时区**格式化（它是同一个
  绝对时刻，只是换了个时区写法）。
- 定时只有**一条**：每分钟巡检一次库（`host.schedule("* * * * *")`，声明持久、重启自动重建），
  每条提醒自己带一个「该响的时刻」（`nextDue`，随库落盘）。这样做有两个原因：① 一次性提醒用
  cron 表达时，错过的时刻会被顺延到明年；② 宿主用 `setTimeout(next - now)` 引爆，延迟超过
  Node 的 24.8 天上限会溢出（详见下面「已知的宿主限制」）。附带好处：停机期间错过的那一次会在
  下次启动时补上；2 分钟内要响的还会再排一个精确定时，避免最多晚一分钟。
- 库文件解析失败（手改坏/半截写）时会先隔离成 `store.json.corrupt-<时间戳>` 再以空库启动，
  **绝不静默覆盖**；导入前也会留一份 `store.json.bak`。
- 「每隔 N 分钟」是**真间隔**（1 分钟 .. 7 天，任意整数）：到点判定用我们自己的 `nextDue`，
  不依赖 cron 表达能力，所以 90 分钟这种也照常走；相位接着上一次到点时刻算，不会因为巡检的
  分钟对齐而慢慢漂。
- **镜像只单向导出**：真相永远是插件自己的 `store.json`，改镜像文件不会回流；清理只删我们
  自己在 `<镜像目录>/.pi-notes-mirror.json` 索引里记过的文件，绝不碰你目录里的其它东西。
- **与内置定时任务的分工**（容易混，特此写清）：
  - 本插件的提醒 = **提醒你这个人**（弹通知/桌面通知/提示音，跟待办/议程/浮窗在一起）。
  - `host` 内置的「定时任务」（issue #184，顶栏后台任务面板 / `schedule` 工具）=
    **到点让 AI 跑一段指令**（无头执行或唤醒原对话，有执行历史）。
  - 所以：想让 AI 到点干活，请直接说「每天 9 点提醒我写日报」让 agent 用 `schedule`（action=create）；
    别在插件里建一条提醒再指望它去执行 —— 那会变成两套「AI 待会儿会做什么」，两边都难查。
- 权限声明：`ui`（顶栏条目 + 通知条）、`http`（插件自己的 `/plugins-api/notes/*` 通道）、
  `tools`（AI 工具）、`fs`（Markdown 镜像写目录，仅在你开启镜像且授权该目录后才会用到）、
  `dom:anchor`（把浮窗挂进宿主锚点范围，**不需要**用户单独授权 DOM）。
- 站内通知条 / 桌面通知 / 提示音 / 提醒时自动展开浮窗，四个开关在浮窗 ⚙ 里（存浏览器
  localStorage）——这几项是「这台设备上的这个浏览器」的偏好，故意不跟着库走。

## 已知的宿主限制（与插件的关系）

`host.schedule` 的 cron 用 `setTimeout(next - now)` 引爆，而 Node 的 setTimeout 延迟超过
2^31-1 ms（≈24.8 天）会**溢出成 1ms**；宿主的 `nextCronFire` 在「一年内找不到」时又会回一个
366 天后的哨兵值。两者相遇就是「1ms 后再触发 → 再排下一次」的死循环（本机实测复现：
`TimeoutOverflowWarning` + 每秒上千次触发 + 每次同步写盘）。

本插件因此**不把远期 cron 交给宿主**：只用一条每分钟的巡检（一定在安全窗口内），远期提醒靠
自己的 `nextDue` 判定。用 `host.schedule` 的其它插件如果传「下次 > 24.8 天」的表达式会踩到这个
坑，修法在宿主侧（`server/plugins.ts` 的 `armCron` 对超长延迟分片，`nextCronFire` 该回 null
而不是哨兵值）。

## 排障

- **顶栏找不到 📓 笔记**：插件没装或激活失败 → 设置 →「界面插件」看它是否带错误信息；
  被隐藏了 → 设置 →「界面布局」里恢复（顶栏条目和别的入口同一套规则）。
- **收不到提醒**：① 提醒列表里那条是不是「已停用」；② 服务端在不在（浮窗底部的小圆点：
  绿=在线、红=离线）；③ 桌面通知默认要浏览器授权，被拒过要去地址栏权限里改回来。
- **提醒时间不对**：按服务器本地时区算，不是浏览器时区（`date` 看一下服务器的时区）。
- **浮窗拖没了**：浮窗 ⚙ →「重置浮窗位置」。
- **想看日志**：设置 →「界面插件」→ 该插件的「日志」（`host.log` 的内存环形缓冲）。

## 开发与回归

```bash
npm run build:server && node tests/notes-test.mjs      # 协议 E2E：清单/HTTP/长轮询/持久化
npm run build && node tests/notes-ui-test.mjs          # 浏览器 E2E：浮窗/拖拽/快速捕获/提醒到点
npx vitest run tests/unit/notes-plugin.test.ts         # 纯函数 + 假宿主（29 例：调度/间隔/镜像/导入…）
```

目录结构：

```
plugins/notes/
├── manifest.json          # 能力声明 + 顶栏条目（notes:toggle）
├── index.mjs              # 服务端：落库 / 持久定时 / HTTP 路由 / AI 工具 / 斜杠命令
└── client/                # 只有这个子树会下发给浏览器（见 server/index.ts 的静态映射）
    ├── entry.mjs          # 客户端入口（view:false + preload:true：顶层代码直接建浮窗，没有 mount）
    ├── store.mjs          # 数据模型与全部纯逻辑（服务端也 import 这一份）
    ├── cron.mjs           # 5 字段 cron 解析与「下次触发」计算（两端共用）
    ├── data.mjs           # HTTP + 长轮询数据客户端（视图与浮窗共用）
    ├── app.mjs            # 界面本体（紧凑浮窗布局）
    ├── panel.mjs          # 可拖拽浮窗外壳（位置/尺寸/最小化）
    ├── settings-form.mjs  # 设置表单（通知开关/语言/导入导出，覆盖层用）
    ├── dom.mjs            # 极简 DOM 构造器（el，四个模块共用）
    ├── prefs.mjs          # 浏览器本地偏好（通知/提示音/语言）
    ├── i18n.mjs           # 中英文案
    └── styles.mjs         # 样式（走宿主主题变量，自动跟随深浅色主题）
```
